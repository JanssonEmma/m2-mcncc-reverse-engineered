# Core database dispatch

Original SHA-256 `85e673aba60da66b68a6844c9e29de5090769249718a9046f868cc5e128ff111`. Source reconstruction is integrated in `ClientManager.cpp`. The peer packet decoder itself is a separate function at `0x0805c400`.

- `AnalyzeQueryResult` `0x0805d270` looks up the peer before global dispatch. QID 18 loads awards, deletes metadata and returns. QID 20 processes guild ranking and QID 23 updates the price list without requiring a peer. If there is a peer, they continue to the ordinary switch and its default log. QIDs 9 to 13 and 19 are acknowledged without handlers. QIDs 0 through 3 share the composite-player handler. Other known callbacks and the unknown query type/query-string log match the original jump table. Every path deletes query metadata and returns 1.
- `UsageLog` `0x0805d570` computes the 3600-sample average, appends a formatted line to usage.txt and resets counters only after a successful open. The original log line uses signed decimal for both average and maximum.
- `Process` `0x0805d650` returns 0 on zero idle pulses, advances the original heartbeat for each pulse, and runs periodic operations in binary order. The one-second handler logs SQL counters, resets them, samples usage, zeros both profiler slots, performs hourly usage logging when applicable, resets the cache-flush counter, updates four caches/logout groups and calls guild, privilege and marriage updates. The detailed SQL log is emitted only at pulse multiples of 50 within that block. The production pt_log format retains the original malformed percent-slash fragment.
- Five-second award polling, ten-second query/item logging and resets, minute time broadcast and hourly money-log flush follow the one-second block in that order. After all pulses, kqueue dispatch handles listener reads and peer read/write/EOF. Receive/send failure and unknown peer events remove the peer. Unknown listener events log the descriptor without removal. Auth peer transfer logging is conditional on g_log. VCardProcess runs after the event loop even when it has no entries.
- Includes needed at merge are DBManager.h, ItemAwardManager.h, GuildManager.h, PrivManager.h, Marriage.h, MoneyLog.h, Peer.h, QID.h and the libthecore heartbeat/FD-watch/logging interfaces. CClientManager methods required beyond the already reconstructed login group include GetUserCount, SendTime, VCardProcess, AddPeer, RemovePeer, ProcessPackets, UpdatePlayerCache, UpdateItemCache, UpdateLogoutPlayer, UpdateItemPriceListCache, RESULT_COMPOSITE_PLAYER, RESULT_SAFEBOX_LOAD, RESULT_SAFEBOX_CHANGE_SIZE, RESULT_SAFEBOX_CHANGE_PASSWORD, RESULT_SAFEBOX_CHANGE_PASSWORD_SECOND, RESULT_HIGHSCORE_REGISTER, __RESULT_PLAYER_DELETE, RESULT_PRICELIST_LOAD and RESULT_PRICELIST_LOAD_FOR_UPDATE. The unit also needs g_test_server, g_log, g_query_count[2] and g_item_count in scope. Usage counters are defined in the staged fragment.
