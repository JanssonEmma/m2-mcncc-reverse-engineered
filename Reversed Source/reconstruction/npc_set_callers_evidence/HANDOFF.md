This package proposes two whole manager methods after the actual `NPC::Set` and its real loader are present. `RegisterNPCVnum` uses the same real directory API and include-path cleanup as `NPC::Set`. `LoadTimerScript` also needs `<climits>` for `UINT_MAX`.

Lookup at `081a77af` returns immediately if already registered. Insertion at `081a77e4` precedes iteration over the live object roots. The original 256-byte buffer is passed to both `snprintf` calls with capacity 255. ELF string bytes at `08232694`, `08218128`, and `082161ec` are `%s/%lu`, `%s`, and `%lu`. Each directory probe logs its formatted path at level zero and calls `opendir`. On success it closes the stream before formatting and logging the decimal vnum, constructs a string, obtains or inserts the NPC, and calls Set at `081a79d9`. There is no break after success and no insertion into the name-to-vnum map. If multiple roots have the vnum directory, each successful probe invokes Set over all roots again. If none is present, registration is still retained and later calls return before probing. Preserve this ordering.

It returns the chosen ID regardless of insertion outcome. No collision scanning or overwrite of existing timer keys.
