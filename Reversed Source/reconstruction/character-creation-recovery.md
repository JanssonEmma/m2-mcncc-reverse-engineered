# Character constructor and manager creation

CHARACTER constructors08124f20/08125770 are now production implementations. Ordinary CEntity/CFSM/CHorseRider, string, container and VID construction is followed by affect-bit/click-trigger initialization, idle/move/battle callback binding and the actual old Initialize routine. Retained constructor bodies corroborate the virtual member-function bindings. The variant audit compares referenced fields only and is not an equivalence certificate.

CHARACTER_MANAGER::CreateCharacter0818c280 allocates a wrapping VID before allocation, constructs a real CHARACTER, calls Create with isPC=(pid!=0), uniquely inserts the VID, and for nonzero PID uniquely inserts folded24-byte name and PID entries. It always returns the new pointer; collisions do not replace earlier entries or roll back other successful insertions. It does not assign m_dwPlayerID: later player-proto loading does that. NPC names are not retained by Create. Defaults in the reconstructed declaration allow a zero PID for NPC callers.

Creation tests run the actual constructor and initialization with real quest flag lookup, seeded identity CRC and actual manager registries. A derived probe verifies virtual idle/move/battle dispatch through the constructor's state bindings. Tests cover full PC names, absent NPC names, high/zero/wrapping VID and PID keys, independent duplicate-name/PID/VID outcomes, and normal manager removal after assigning the proto player-ID field.

The CHARACTER constructor test substitute is removed. The remaining CHARACTER destructor, unrecovered state/protocol/horse overrides, quest Lua lifecycle and sector ownership remain explicit test boundaries. Tests do not claim full character resource teardown. Descriptor slice tests now link actual entity/FSM/horse constructor dependencies plus explicit remaining virtual/destructor fixtures. The old manager-only aborting character methods and duplicate isolated sector fixture have been removed.

CHARACTER Destroy081274f0 is staged in character-destroy-ghidra.json, not yet implemented. It depends on real shop, dungeon, exchange, victim, stone, sync, target, item, party, safebox and affect cleanup, event cancellation and ownership. destruction-dependency-types.json retains full old by-value declarations for needed classes across their original compilation units. No partial no-op production teardown has been introduced.
